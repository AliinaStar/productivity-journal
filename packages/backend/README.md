# Backend — BCR Report API

FastAPI backend for the BCR productivity journal. Handles authentication, data storage, embedding generation, and AI report creation.

## Stack

| Component | Technology |
|-----------|-----------|
| API framework | FastAPI 0.135+ |
| Database | PostgreSQL 17 + pgvector |
| ORM / migrations | SQLAlchemy (async) + Alembic |
| Embeddings | `Alibaba-NLP/gte-multilingual-base` · 768-dim |
| RAG pipeline | LangGraph |
| LLM | OpenAI GPT-4o (structured output) |
| Scheduler | APScheduler (`AsyncIOScheduler`) |
| Email | Resend (passwordless OTP) |
| Observability | Langfuse |
| Runtime | Python 3.11 · uv |

## Running with Docker (recommended)

```bash
cp .env.example .env
# Edit .env — at minimum fill in OPENAI_API_KEY, RESEND_API_KEY, EMAIL_FROM

docker compose up --build
```

`start.sh` runs `alembic upgrade head` before starting uvicorn, so migrations apply automatically on every start.

The API is available at `http://localhost:8000`.  
Interactive docs: `http://localhost:8000/docs`.

## Running locally

```bash
# Install uv (if not already installed)
pip install uv

# Install dependencies
uv sync

# Start PostgreSQL separately (or point to an existing instance)
# Then apply migrations:
uv run alembic upgrade head

# Start the API
uv run uvicorn src.main:app --reload --port 8000
```

## API reference

All endpoints except `/auth/*` and `/health` require the `X-User-ID` header (integer returned by `/auth/verify-code` or `/auth/dev-login`).

### Auth

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/auth/send-code` | Generate OTP and email it |
| `POST` | `/auth/verify-code` | Validate OTP, create user if new, return `user_id` |
| `POST` | `/auth/dev-login` | Skip OTP — dev mode only |

### Goals

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/goals` | List goals for current user |
| `POST` | `/goals` | Create a goal |
| `PATCH` | `/goals/{id}` | Update title or description |
| `DELETE` | `/goals/{id}` | Delete a goal and its entries |

### Entries

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/entries` | List all entries for current user |
| `POST` | `/entries` | Create entry (auto-generates embedding) |
| `PATCH` | `/entries/{id}` | Update entry (re-embeds if note changes) |

### Reports

| Method | Path | Description |
|--------|------|-------------|
| `POST` | `/reports/generate` | Run RAG pipeline and save report |
| `GET` | `/reports` | Fetch a stored report by period and date |
| `GET` | `/reports/list` | List all stored reports for a period |

### Users

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/users/me` | Get current user profile |
| `PATCH` | `/users/me` | Update language or gender |

### Health

| Method | Path | Description |
|--------|------|-------------|
| `GET` | `/health` | Returns `{"status": "ok"}` |

## RAG pipeline

Reports are generated by a LangGraph pipeline with two distinct paths depending on the period:

```
                      ┌─────────────────┐
                      │   /reports/     │
                      │    generate     │
                      └────────┬────────┘
                               │
                    ┌──────────▼──────────┐
                    │   retrieve_entries  │
                    │  (load DB entries)  │
                    └──────────┬──────────┘
                               │
              week ────────────┤
                               │   month / year
                    ┌──────────▼──────────┐
                    │  collect_reports    │
                    │ (sub-period from DB)│
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │ generate_summary    │
                    │ (LLM, per-goal)     │
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │  retrieve_similar   │
                    │  (MMR from pgvector)│
                    └──────────┬──────────┘
                               │
                    ┌──────────▼──────────┐
                    │   create_report     │
                    │  (GPT structured    │
                    │   output → JSON)    │
                    └─────────────────────┘
```

**Week path:** current entries → `create_report` directly.

**Month / Year path:** loads sub-period reports from DB → compresses per-goal summaries with LLM → retrieves historical context via MMR → generates structured report.

### MMR retrieval

Retrieval uses Maximal Marginal Relevance (λ = 0.5) to balance relevance and diversity:

```
mmr_score = 0.5 × relevance(candidate, query)
          − 0.5 × max_similarity(candidate, already_selected)
```

The embedding model (`gte-multilingual-base`) is loaded once at startup and runs in a dedicated single-threaded executor to keep its rope cache thread-safe.

## Automatic report generation

APScheduler runs cron jobs at these UTC times:

| Period | Trigger | Description |
|--------|---------|-------------|
| Week | Monday 00:01 | Generate weekly report for all users |
| Month | 1st of month 00:01 | Generate monthly report |
| Year | 1 Jan 00:01 | Generate yearly report |

Up to 10 pipeline runs execute concurrently (semaphore). Reports are stored in the DB and fetched by the frontend on demand.

## Database migrations

```bash
# Apply all pending migrations
uv run alembic upgrade head

# Create a new migration after editing models.py
uv run alembic revision --autogenerate -m "describe change"

# Roll back one step
uv run alembic downgrade -1
```

## Tests

```bash
uv run pytest
```

The suite mixes pure unit tests (JWT, settings, helpers) with API integration
tests that run against a throwaway `reporting_system_test` database on the same
Postgres instance (created automatically on first run). Embeddings, email and
the RAG pipeline are stubbed, so tests run offline — only Postgres needs to be
up (`docker compose up -d db`). Auth/ownership tests assert that one user can
never read or modify another user's goals, entries or reports.
